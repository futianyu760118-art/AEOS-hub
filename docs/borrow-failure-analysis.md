# 跨系统借调失败分析（2026-10-23）

> 数据源：`data/borrow-orders.json`。统计口径：`status = failed` 的借调单。
> 目的：为 A2 试点启动前的失败治理提供根因、归属和验收口径。

## 1. 结论先行

| 指标 | 数值 |
|---|---:|
| 总借调单 | 74 |
| 完成 | 57 |
| 失败 | 17 |
| 失败率 | **23.0%** |
| 近 3 天失败率 | **21.4%**（15 / 70） |

**三个关键判断：**

1. **23% 不是历史噪音**：近 3 天仍为 21.4%，说明问题仍在发生。
2. **最大单点是 PLM 登录过期**：10 张失败单（占全部失败 59%）的报错都是“PLM 登录失败: 未登录或登录已过期”，PLM 提供方失败率 40%。
3. **中台侧主要是推理输出解析和连通性**：3 张“未能从模型输出中提取到有效 JSON”，2 张“中台不可达”，1 张 HTTP 401。

## 5. 根因与治理动作

### 5.1 PLM 登录过期（10 张，最大单点）

**现象：** 所有报错都是“PLM 登录失败: 未登录或登录已过期”。

**根因：** PLM 侧会话过期后没有自动刷新；执行体把会话失效当成普通执行失败返回，Hub 只能看到 `EXECUTION_FAILED`。

**归属：** PLM 团队（主）、Hub（辅）。

**动作：**

- PLM 执行体在登录态失效时自动重新登录，并重试当前任务一次。
- 网关/执行体暴露 `AUTH_EXPIRED` 错误码，不要混在 `EXECUTION_FAILED` 里。
- 健康检查增加“PLM 登录态”探测；失败时明说“登录过期”，不要返回“没有数据”。
- Hub 侧对 `AUTH_EXPIRED` 不自动重试超过 1 次，避免把登录问题放大成雪崩。

**验收：** 连续 7 天 0 张“登录过期”失败单。

### 5.2 中台推理输出无法解析 JSON（3 张）

**现象：** “中台大模型调用失败：未能从模型输出中提取到有效 JSON: line 1 column 1 (char 0)”。

**根因：** 中台推理输出不是稳定 JSON；解析器直接失败，没有降级或重试。

**归属：** 中台团队（主）、Hub（辅）。

**动作：**

- 中台推理接口返回结构化 `result`，或在网关侧做 JSON 修复/重试。
- 失败时返回 `INVALID_RESULT`，附带原始输出摘要和 `data_confidence`。
- Hub 侧对 `INVALID_RESULT` 不伪造结论，明确标记“数据置信度不足”。

**验收：** 连续 7 天 0 张 JSON 解析失败；所有推理结果可被 schema 校验。

### 5.3 中台不可达 / 401（3 张）

**现象：** 2 张 `fetch failed`，1 张 `/common/ping` HTTP 401。

**根因：** 网络/上游不可达，或中台令牌/登录态失效。

**归属：** 中台团队 / 网络（主）、Hub（辅）。

**动作：**

- 中台侧做健康检查和令牌刷新。
- Hub 侧在派单前做一次轻量健康探测；不可达时快速失败，不占用 30 秒派单超时。
- 对 401 返回明确 `UPSTREAM_AUTH_FAILED`，不要归为“没有数据”。

**验收：** 不可达时派单前失败，P95 失败耗时 < 1 秒；401 可定位到令牌/配置。

### 5.4 Hub 重启孤儿（2 张）

**现象：** “Hub 重启导致在途任务中断，请重新发起”。

**根因：** Hub 重启后无法恢复在途 run，只能标记失败。

**归属：** Hub。

**动作：**

- 借调单支持“失败可重试”，保留原 `requestId` 的幂等语义。
- 长任务异步化，Hub 重启后从借调单 + run 记录对账。
- 对可安全重试的只读能力，自动重试一次（需幂等）。

**验收：** Hub 重启后，失败单可一键重试；重复执行不产生重复副作用（只读能力天然幂等）。

### 5.5 派单超时 / 推理超时（2 张）

**现象：** 1 张 30 秒派单超时；1 张推理超过 170 秒。

**根因：** 超时参数固定，未按能力区分；执行面没有及时回 `run_update`。

**归属：** Hub + 提供方。

**动作：**

- 超时参数化：派单 30 秒、查询 60 秒、推理 240 秒可按能力覆盖。
- 执行面在每个阶段回 `run_update`，Hub 据此判断是“还在跑”还是“卡住”。
- 网关心跳 + 在途 run 数进入 SLO。

**验收：** 超时可按能力配置；超时失败可看到最后阶段。

## 6. 总体验收口径

| 指标 | 目标 |
|---|---|
| 借调总体失败率（7 天窗口） | < 5% |
| PLM 提供方失败率（7 天窗口） | < 10% |
| 失败单可归因率 | 100%（`error.code` + `stage` + 归属） |
| 登录过期类失败 | 0 |
| JSON 解析类失败 | 0 |

## 7. 复现方式

```bash
node -e "const os=require('./data/borrow-orders.json').orders; const f=os.filter(o=>o.status==='failed'); console.log(os.length, f.length, (f.length/os.length*100).toFixed(1)+'%'); console.table(f.map(o=>({from:o.fromSystem,to:o.providerSystem,cap:o.capability,code:o.error&&o.error.code,msg:o.error&&o.error.message})))"
```
