# M01 局域网演示部署 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让同一私有网段内的笔记本可通过 `https://192.168.0.23:9444` 安全访问 AEOS Hub，并通过 `https://192.168.0.23:9443` 完成现有 Keycloak 登录。

**Architecture:** 保留 Hub 作为宿主机 Node 进程，以及现有 Keycloak/PostgreSQL/Caddy Docker 栈；只让 Caddy 公开两个 TLS 端口。Hub 以安全 Cookie 和 HTTPS 回调运行，Caddy 将 Hub HTTPS 请求代理到宿主机私有 HTTP 端口；Keycloak 的 PostgreSQL、管理端口和 Hub 的 8790 端口不向局域网公开。

**Tech Stack:** Node.js/TypeScript、PowerShell、Docker Compose、Caddy 2、Keycloak 26、PostgreSQL 16、Windows Defender Firewall。

**Spec:** `docs/auth/m01-handover.md` §7（局域网硬约束），本计划将其由“仅回环”演示环境扩展为“私有网段 TLS 演示环境”。

## Global Constraints

- 只修改 `deploy/m01/`、`scripts/`、M01 部署文档及其测试；不修改任务中心、Agent、MCP、业务看板、证据链或业务数据代码。
- Hub 只接受 HTTPS 回调；`AEOS_COOKIE_SECURE=1`，`NODE_ENV=production`，禁止把非回环 HTTP 暴露给浏览器。
- Keycloak PostgreSQL、Keycloak HTTP 管理端口与 Hub 8790 端口不得公开；Docker 卷和现有 Realm/用户不得删除或重建。
- 使用既有 Caddy 内部 CA；仅导出公共根证书到交付目录，绝不输出 CA 私钥、Keycloak 管理员密码、数据库密码或 OIDC client secret。
- Windows 防火墙仅在 Private Profile 放行 TCP 9443/9444，RemoteAddress 限制为 `LocalSubnet`；不得开放到 Public Profile。
- Keycloak issuer、Hub callback、client redirect URI、web origin 和登录时浏览器地址必须统一使用 `192.168.0.23`，不得混用 `localhost`。

## Review Focus

- 其他主机访问 Hub 时，浏览器必须只走 HTTPS 9444；将该行为在 Task 3 的端点和响应头验收中验证。
- Keycloak 返回的授权码必须精确回到 `https://192.168.0.23:9444/api/auth/callback`；在 Task 2 读取 client 配置并在 Task 4 做浏览器闭环验证。
- 访问设备未信任 Caddy 根证书时应显示证书不受信任而非静默降级；在 Task 4 的客户端交付步骤中明确验证。
- Docker 到宿主机 Hub 反向代理失败时，Caddy 不得回退到公开 8790；在 Task 3 检查 `host.docker.internal:8790` 连通性，并保持 8790 无防火墙规则。
- 服务恢复为原本机模式时，已有 Keycloak 数据、命名卷和用户不得丢失；在 Task 5 以备份原 `.env` 和明确回退步骤验证。

- **Step scan:** each task has one owner boundary and a checkable output; external firewall and Keycloak configuration are isolated from application source.
- **Type consistency:** the endpoint variable names are introduced in Task 1 and consumed consistently by Tasks 2–4.
- **Review Focus:** each listed failure mode is pinned to Task 2, 3, 4, or 5 verification.
- **Proportion:** the plan does not prescribe task-center/Agent changes and uses existing Node, Docker, Caddy, and Keycloak components.
