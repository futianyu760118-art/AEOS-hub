# 管理者首页模块折叠实施计划

**目标：** 管理者首页的详细模块默认折叠、按需展开；不改变看板数据、接口、Agent、Guard、Result/Verify 或经营事项中心逻辑。

**实现方式：** 仅修改页面展示层。保留现有动态数据元素及其 `id`，在 `public/index.html` 为详细模块增加可访问的标题折叠按钮与内容容器，在 `public/style.css` 增加折叠和响应式样式，并用少量浏览器端脚本同步 `aria-expanded` 与内容显示状态。

## 范围与约束

- 只修改 `public/index.html` 和 `public/style.css`；不修改服务端、API、数据加载、MCP、Agent 和持久化代码。
- 顶部“当前目标”和概要指标保持展开。
- 默认收起以下详细模块：未来经营风险、订单交付风险、物料齐套、异常与质量、生产协同、TOP 决策、能力与治理脉冲。
- 页面刷新后恢复默认折叠；允许同时展开多个模块。
- 每个切换按钮必须使用原生 `button`，带 `aria-expanded="false"`、`aria-controls`，支持键盘操作。
- 既有“进入事项”“交给 Agent 分析”等按钮必须保持原有行为，不得因折叠逻辑而误触发。

## 实施任务

### 任务一：调整管理者首页结构

**修改文件：** `public/index.html:180-238`

1. 为每个详细模块增加 `dashboard-module-toggle` 标题按钮及唯一的 `dashboard-module-content` 内容容器。
2. 模块初始状态为折叠：标题按钮 `aria-expanded="false"`，内容容器使用 `hidden`。
3. 保留风险表、物料表、质量表、生产表、决策列表等所有既有元素的 `id`，不改变数据刷新代码的写入位置。
4. 增加局部事件处理：仅在点击标题按钮时切换所在模块的折叠状态、`aria-expanded` 与 `hidden`；不阻断既有按钮事件。

### 任务二：增加折叠样式

**修改文件：** `public/style.css:445-520`

1. 为切换标题提供与现有看板一致的文字、箭头和悬停样式。
2. 为键盘焦点提供清晰可见的焦点环。
3. 只隐藏内容容器，不能覆盖既有表格、网格或滚动样式。
4. 展开时旋转箭头；窄屏下标题、箭头和现有操作按钮不重叠、不造成横向溢出。

### 任务三：验证

1. 运行 `npm run test:dashboard; npm run check:types`，预期通过。
2. 打开管理者首页，刷新数据后逐个展开模块，确认数据仍显示在原位置。
3. 检查键盘 Tab、Enter、空格的操作效果和 `aria-expanded` 状态。
4. 运行 `docker compose up -d --build aeos-hub`，确认服务健康，且首页详细模块均默认折叠。

## 验收标准

- 管理者首页初始只展示目标与核心指标，详细模块默认收起。
- 任意模块可以独立展开/收起，且不影响后台数据刷新。
- 原有导航、Agent 分析及其他标题栏按钮行为不变。
- 桌面端与窄屏界面均可正常使用。
- 不产生服务端、核心逻辑或数据结构改动。
