# 强制账号密码登录实施计划

> 状态：已实施、待配置部署密码；关闭浏览器或重启容器后，访问 AEOS Hub 必须重新输入账号和密码。刷新当前已登录页面不要求重复登录。

## 目标与边界

- 用服务端验证替换现有仅保存在浏览器 `localStorage` 的 `demo/demo` 演示校验。
- Docker 部署默认开启登录保护，移除 `HUB_NO_AUTH: "1"` 这一绕过开关。
- 登录成功后只签发**浏览器会话 Cookie**：不设置 `Max-Age` 或 `Expires`，关闭浏览器即失效；容器重启时内存会话也失效。
- 不改变业务数据、面板、MCP 只读调用、审批逻辑或已有页面功能。
- 不在仓库、页面或日志中写入明文账号密码；部署凭证从未提交的本地 `.env` 读取。

## 设计

1. **部署配置**
   - 新增 `AEOS_LOGIN_USERNAME` 与 `AEOS_LOGIN_PASSWORD` 环境变量说明；真实值只放在本机 `.env`。
   - `docker-compose.yml` 将认证设为开启，并把上述变量传入容器；若未配置则启动时明确失败，避免意外裸奔。
   - 更新 `docker-compose.env.example` 和 README，删除 `demo/demo`、分享链接和“记住 30 天”的说明。

2. **服务端认证**
   - 在 `src/server.ts`（或提取的小型认证模块）集中处理凭证读取、恒时密码比对、随机会话 ID、会话撤销与 Cookie 生成。
   - 增加 `POST /api/auth/login`：限制请求体大小、仅接受字符串账号/密码、按现有 `validOrigin` 检查来源；失败统一返回 401，不泄露是账号还是密码错误。
   - 会话记录只保存在进程内存；通过 `HttpOnly; SameSite=Lax; Path=/` Cookie 传递，故 JavaScript 无法读取，关闭浏览器或容器重启后不可再用。
   - 仅把登录页所需静态文件、`/healthz` 与登录接口设为公开；全部业务 API、运行数据、WebSocket 和图片资源必须验证新会话。
   - `POST /api/auth/logout` 删除服务端会话并清除认证 Cookie；保留并清理现有 `aeos_session`，把其 30 天持久化属性改为浏览器会话级，避免残留标识误导使用者。

3. **前端交互**
   - `public/app.js` 的登录提交改为调用 `/api/auth/login`；不再保存“已登录”状态到 `localStorage`，以服务端 401 为唯一登录状态来源。
   - 初始化时先请求受保护的轻量接口：成功进入工作区，401 则显示登录页；接口遇到 401 时关闭 WebSocket、清空界面状态并回到登录页。
   - 退出按钮调用服务端登出并清空旧版本遗留的 `localStorage` 键；登录页文案改为“由管理员配置账号密码”，不展示默认凭证。

## 实施步骤

1. 编写认证会话单元测试：正确/错误凭证、缺少配置、会话 Cookie 无持久化属性、登出撤销、容器重启（新认证服务实例）后原 Cookie 无效。
2. 实现服务端认证与公开路由白名单；接入 HTTP 与 WebSocket 鉴权，替换原 `access-token.txt`/`hub_token` 分享口令路径。
3. 改造前端登录、启动探测与 401 处理，移除 `demo/demo` 和持久本地登录标记。
4. 更新 Docker Compose、示例环境文件与 README；在实际 `.env` 配置用户指定的账号和密码（该文件保持 git 忽略）。
5. 运行类型检查、现有仪表盘测试、新认证测试和格式检查；用 Docker 重建并验证：未登录 401、登录成功、刷新保持、关闭浏览器/重启容器后需要重登、退出后无法访问。

## 审查重点

| 重点 | 验证方式 |
| --- | --- |
| 不能绕过认证 | 直接访问 API、WebSocket、图片资源均被拒绝；仅登录静态资源和健康检查公开。 |
| 不会“记住登录” | `Set-Cookie` 不含 `Max-Age`/`Expires`；关闭浏览器和重启容器后旧 Cookie 无效。 |
| 密码不泄露 | 未进入仓库、页面、网络响应、启动日志或错误信息；比较使用恒时比较。 |
| 登出彻底有效 | 服务端会话撤销且 Cookie 清除后，旧 Cookie 与旧 WebSocket 都无法继续访问。 |
| 不影响现有功能 | 登录后仪表盘、四个独立看板、业务查询和 WebSocket 更新照常可用。 |

## 需要你确认的部署约定

- 默认账号建议使用 `manager`；密码由你在本机 `.env` 设置，**不要在聊天里发送真实密码**。
- 此方案的“每次”定义为：每次重新打开浏览器或服务重启时必须登录；同一浏览器窗口内刷新不重复要求输入。如果你希望“每打开一个新标签也必须重输”，需要使用一次性短会话，体验会明显更差。
