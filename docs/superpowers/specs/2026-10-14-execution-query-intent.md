# 执行面聊天查询意图规范

## 目标

让执行面聊天将有限范围的中文查询准确转换为中台只读白名单接口与显式参数，禁止将无法识别的日期、数量、编号或业务条件静默降级为全量查询。

## 范围

- 覆盖八类查询：缺料、齐套、订单、库存、供给、质量、生产和供应商；每一类都支持其上游已公开的筛选字段，而不是只为示例编号做匹配。
- 编号可含数字前缀和 `.`、`-`、`:`，例如 `3.1.JFX27-B1WA45-ZJ2-10-001`；“型号/名称/关键字”走接口的模糊检索字段，“物料编码/订单号/工单号”等明确编号走精确字段。
- 支持“近 N 天”、`YYYY-MM-DD 至 YYYY-MM-DD`、`前 N 条`和`第 N 页`；日期范围和分页始终同时传递给中台。
- 解析八类业务各自可表达的状态、风险、供给来源、仓库、客户、车间或关键料条件，并只发送该接口契约中存在的字段。
- 当中台接口本身没有某种筛选能力（例如供给接口无法按物料名称模糊检索）时，明确要求可用的业务锚点，不伪造字段或退化成全量查询。
- 相对日期映射为目标接口的实际日期字段；“近 N 天”按含当天的 N 个自然日计算。
- 每一类查询必须包含精确业务锚点、明确日期范围或显式“前 N 条”限制之一；否则返回面向用户的澄清错误，不派单。
- 所有派单均带 `page=1` 和受限 `page_size`；`N` 必须为 1–100 的正整数。
- 缺料、齐套必须带订单/需求或物料锚点；库存必须带物料锚点；质量、订单、供给、生产可使用其对应日期范围或显式数量限制。
- 所有路径继续受既有执行面白名单约束，仅执行只读查询。
- 控制层必须校验并保留“用户意图 → 派发参数 → 中台分页响应 → 用户答案”的完整链路。`total` 仅表示当前筛选范围的总匹配数，不能被表述为本页返回数。
- 八类查询回答必须分别展示本页返回数、当前页码、每页条数与总匹配数；界面只展开本页前 12 条时，须与后续分页记录明确区分。
- 中台响应若出现页码/每页条数与请求不一致、`total < items.length`、单页行数超出 `page_size` 等契约异常，必须在答案中标示“数据校验提示”，不得静默作出完整性结论。

## 非目标

- 不改中台上游接口、认证、WebSocket 协议或执行面连接机制。
- 不实现通用大模型语义解析；本期仅覆盖明确的中文关键词、编号、日期、数量和已登记筛选条件表达。
