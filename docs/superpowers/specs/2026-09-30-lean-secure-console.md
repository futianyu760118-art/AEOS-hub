# AEOS Hub 精益安全控制台规格

## 目标

把当前试点控制台收敛为面向经营管理者的最小工作台：风险总览、待办闭环、只读智能分析。系统配置、运行时资源与审计属于受控管理能力，不再作为日常工作的一级导航。安全优先于自动化和视觉改造。

## 用户界面

- 一级工作区只保留“经营总览”“经营闭环”“智能分析”；“系统管理”仅对管理员显示。
- 经营闭环整合 Attention、经营事项和 Inbox：默认先展示待人工处理的事项，再展示关联风险与消息；不删除历史数据和后端能力。
- AI 港湾、Agent 小队、Capability Registry、原始 Evidence 迁入“系统管理”二级页，并按角色隐藏；它们不出现在命令面板、欢迎页或常规导航。
- 所有经营卡片、表格、弹窗和搜索中不直接显示 `evidence_ref` / `control-platform://…`。正常用户只看到“证据已关联”或“数据待确认”；审计员可在独立、按需打开的证据详情中查看完整引用。
- 系统使用统一的中文优先无衬线字体与明确的标题、正文、数据、审计四级字阶。原始标识符只在受控审计视图以等宽字体显示。

## 认证、授权与会话

- 移除前端 `demo/demo` 身份判断；登录必须由服务端验证密码并签发 HttpOnly 会话 Cookie。
- 首版采用本地账号库：首次启动时要求管理员配置 `AEOS_BOOTSTRAP_ADMIN_USERNAME` 和 `AEOS_ADMIN_PASSWORD_HASH`（Node `scrypt` 格式），未配置即拒绝启动；不保留默认账号或明文密码。管理员可在受控管理区创建后续本地账号并分配角色。
- 角色固定为 `manager`、`operator`、`auditor`、`admin`：管理者阅读经营数据；操作员可记录人工决策；审计员可读原始 Evidence；管理员可管理运行时、模型、MCP、港湾和账号。
- 所有 HTTP API 和 WebSocket 都必须校验服务端会话与角色。写接口还必须要求同源 Origin 与 CSRF token；无 Origin 的浏览器请求不得借由兼容分支绕过检查。
- 禁止 `--no-auth` 与 `HUB_NO_AUTH`；局域网监听只允许部署在 TLS 反向代理之后，并要求 `AEOS_PUBLIC_ORIGIN=https://…` 与 Secure Cookie。默认继续仅监听本机。
- 令牌不再通过 URL 查询参数传递；登录、退出、会话轮换与失败限流均记录不含敏感字段的审计事件。

## 数据边界

- 移除定时 Autopilot：不保留计划、运行入口、后端调度器、API 或本地运行记录；已有经营事项和 Inbox 数据必须保留。
- AEOS 作为决策“大脑”由服务进程每 5 分钟主动执行一次只读经营数据刷新，并缓存最近一次快照；刷新不创建事项、不发送承诺、不写入业务系统。页面读取缓存并明确显示数据基准时间，刷新失败时必须保留并标注上次结果“数据置信度不足”。
- 原始证据引用仍保存在后端事项与审计数据中，用于追溯；UI 隐藏不改变证据链或 Agent 的引用要求。

## 非目标

- 本次不删除后端领域数据、历史 Evidence、会话或 MCP Capability。
- 本次不接入企业 SSO；后续可在认证接口替换为 OIDC/SAML。
- 本次不放开任何业务写能力，也不把 Agent 建议变成自动执行。
- 在用户再次确认前，保留现有 `demo/demo` 演示登录，不实施本规格中的服务端认证迁移。
