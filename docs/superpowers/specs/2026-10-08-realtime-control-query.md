# 实时中台查询改造说明

## 目标

把 Attention 中心中的“搜索 + 实时核查中台”改成一次即可理解、无需记住勾选和回车操作的查询工作台，同时修复中台分页和产能查询的兼容问题。

## 要求

- 保持所有 company-control 调用为只读，不写业务系统或 Evidence。
- 修复 `production_capacity_list` 传参，使用中台契约要求的 `date_start` 和 `date_end`。
- 分页必须显式处理中台返回的 `next_cursor`；达到安全页数上限或返回异常时，继续标记为部分数据，不能伪装成完整结果。
- 实时查询允许空关键词并展示已读取的事项；输入关键词时按订单号、工单号、异常号、物料、客户、责任人、状态和 Evidence 匹配。
- 用户通过明确的“核查中台”按钮发起查询，不再需要先勾选开关再按 Enter。
- 查询界面需要清楚区分：没有匹配项、数据部分完成、数据过期、能力返回格式不匹配和完全不可用。
- 生产工单和产能读取结果应可作为“生产协同”范围的实时查询概览；数据不足时只提示置信度问题，不编造业务结论。

## 非目标

- 不修改中台业务数据。
- 不把过期、缺失或部分分页数据提升为高置信度。
- 不在本次改造中接入新的业务系统或改变 Agent 的审批权限。
