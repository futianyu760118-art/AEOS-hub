# 中台生产协同数据时效修复交接文档

> 版本：V1.0 · 2026-09-29  
> 交接对象：中台平台组 / 生产数据供给维护人  
> 接入链路：生产业务系统 → 中台数据供给 API → `company-control` MCP → AEOS Hub  
> 优先级：P0（数据时效与风险判断边界）  
> 范围：只读生产协同数据，不涉及生产业务写操作

## 1. 问题现象

AEOS Hub 管理者首页的“中控数据基准”显示：

| 业务模块 | 当前显示的数据基准 |
|---|---:|
| 订单交付 | 09/29 12:46 |
| 物料齐套 | 09/28 15:28 |
| 异常与质量 | 09/29 10:30 |
| 缺料 | 09/28 15:28 |
| 生产协同 | **08/06 15:44** |

生产协同卡片同时显示“工单 1000 条、工序 0 条、关联 2 条”。这说明问题不是前端将所有日期写死，而是**生产协同链路返回了明显早于其他业务域的数据快照**。

当前日期为 2026-09-29，生产数据基准 2026-08-06 已超过正常经营分析时效，不得继续以正常数据参与订单交付或生产风险判断。

## 2. 根因判断

### 2.1 中台生产接口返回旧快照

请优先核查以下五个接口的原始响应：

```text
GET /external/production/work-orders/list
GET /external/production/operations/list
GET /external/production/order-links/list
GET /external/production/reports/list
GET /external/production/capacity/list
```

重点检查每个响应中的：

- `data_as_of`
- `data_confidence`
- `stale`
- `generated_at`
- `updated_at` 或数据源最后同步时间

目前现象很可能是生产快照、ETL 任务或数据供给接口仍停留在 8 月 6 日，而订单、齐套、质量链路已经刷新到 9 月 28—29 日。

### 2.2 现有适配层无法识别“有字段但已过期”

`company-control` 生产适配目前主要校验时效字段是否存在、格式是否合法，以及上游是否显式返回 `stale=true`。如果中台返回：

```json
{
  "data_as_of": "2026-08-06T07:44:00Z",
  "data_confidence": "high",
  "stale": false
}
```

即使实际已经过期，只要 `stale` 没有被正确设置，调用链仍会把它当成可用数据。

### 2.3 多个生产接口时间不一致时需要保留分域时效

Hub 当前生产汇总会把多个生产接口的时间合并展示。中台必须保证每个接口都返回自己的真实快照时间；不得使用一个固定时间覆盖全部生产域，也不得用当前时间填充缺失的 `data_as_of`。

## 3. 中台必须完成的修改

### 3.1 修复生产数据同步任务

请确认生产工单、工序、订单关联、报工、产能五类数据的来源和同步任务：

| 数据域 | 需要确认 |
|---|---|
| 工单 | 是否仍读取 08/06 的静态快照；最近一次成功同步时间；是否有增量遗漏 |
| 工序 | 为什么当前显示 0 条；是无数据还是未执行查询/映射失败 |
| 订单关联 | 关联数量是否为当前快照结果，是否支持分页完整返回 |
| 报工 | 是否为最新生产日报；累计口径是否包含更正/撤销 |
| 产能 | 查询日期窗口是否正确；工作日历和排产快照是否刷新 |

同步任务修复后，五个接口都应返回真实的最新可用快照时间。无法刷新时必须明确返回旧数据/低置信度，不得只保留 `high`。

### 3.2 统一返回信封

五个接口均应返回以下字段：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "data_as_of": "2026-09-29T15:44:00+08:00",
    "data_confidence": "high",
    "stale": false,
    "warnings": []
  }
}
```

字段语义：

| 字段 | 要求 |
|---|---|
| `data_as_of` | 数据实际快照时间，必须带时区；不得用接口响应时间冒充业务快照时间 |
| `generated_at` | 本次 API 响应生成时间；与 `data_as_of` 分开保留 |
| `data_confidence` | 仅允许 `high`、`medium`、`low`；缺字段不能默认为 `high` |
| `stale` | 数据超过约定时效或同步任务失败时为 `true` |
| `warnings` | 描述部分同步、字段缺失、分页不完整、源系统延迟等情况 |
| `total` | 当前过滤条件下的总记录数，不是当前页记录数 |
| `items` | 当前页数据；空数组只能表示查询范围内确实无记录 |

### 3.3 时间和时区规范

- 所有 ISO 时间必须包含 `Z` 或明确的 `+08:00` 偏移。
- 推荐统一返回 UTC 或带 `+08:00` 的 ISO 8601，不允许返回无时区字符串。
- `data_as_of` 表示源数据快照时间，不表示 Hub 请求时间。
- `updated_at` 表示记录更新时间，不得替代整批数据的 `data_as_of`。
- 禁止把缺失时间填为 `now`。

示例：

```text
正确：2026-09-29T15:44:00+08:00
正确：2026-09-29T07:44:00Z
错误：2026-09-29 15:44:00
错误：缺失时直接填当前服务器时间
```

### 3.4 明确过期策略

建议生产协同数据默认有效期为 24 小时，最终阈值由生产数据负责人确认。

| 情况 | `data_confidence` | `stale` | MCP/Hub 行为 |
|---|---|---:|---|
| 快照在有效期内且同步完整 | `high` | `false` | 可用于只读展示和分析 |
| 快照较旧但仍可参考 | `medium` | `false` | 展示并提示需关注 |
| 超过有效期 | `low` | `true` | 展示但禁止形成确定性风险结论 |
| 无法确认时间或置信度 | `low` | `true` | 返回结构化不可用/置信度不足 |
| 源系统调用失败 | 不返回伪造数据 | — | 返回结构化错误 |

过期错误建议：

```json
{
  "error": {
    "code": "STALE_DATA",
    "message": "生产协同数据最后同步于 2026-08-06T15:44:00+08:00，已超过 24 小时有效期",
    "retryable": true
  }
}
```

## 4. 五个接口的专项要求

### 4.1 `production_work_orders_list`

- 返回当前生产任务单快照，不得只返回历史静态种子数据。
- `total` 必须与过滤条件一致。
- 工单必须有稳定主键：`work_order_id` 或 `work_order_no`。
- 保留 `status_raw`，同时返回标准 `status`。
- 计划完工时间、实际开始/结束时间缺失时返回 `null`，不得补造。

### 4.2 `production_operations_list`

- 当前页面显示“工序 0 条”，必须确认是确实没有工序，还是查询锚点/映射问题。
- 需要明确 `order_no`、`work_order_id` 的查询锚点要求。
- 无法按工单查询时，应在响应 `warnings` 中说明，不得返回看似完整的空结果。

### 4.3 `production_order_links_list`

- 订单与工单关系必须来自正式关联表。
- 禁止仅按产品编码、客户名称或工单编号前缀推断关联。
- 多页结果必须完整返回，并保留 `link_id`、订单号、订单行号和关联数量。

### 4.4 `production_reports_list`

- 明确累计报工还是增量报工口径。
- 支持更正、撤销或版本字段，避免重复计数。
- `reported_at` 与 `updated_at` 分开返回。

### 4.5 `production_capacity_list`

- `date_start`、`date_end` 必须真正限制查询范围。
- 返回排产版本、工作日历版本和 `capacity_date`。
- 缺少标准工时、日历或基础产能条件时，负荷率返回 `null`，不能自行计算。

## 5. 联调验收标准

### 5.1 时效验收

逐个调用五个接口，检查：

- `data_as_of` 不再是 2026-08-06；
- 或者，如果确实没有新数据，必须返回 `stale=true` / `data_confidence=low`；
- 不允许缺少时间时默认填当前时间；
- 不允许旧数据标记为 `high + stale=false`。

### 5.2 数据完整性验收

- 工单数量、订单关联数量、工序数量与中台页面/数据库统计口径一致；
- 工序为 0 时能说明“无记录”还是“未能查询”；
- 分页总数和当前页数量一致；
- 五个接口的 `data_as_of`、`data_confidence`、`stale` 可独立核验。

### 5.3 Hub 页面验收

刷新 Hub：

```text
GET /api/dashboard?refresh=1
```

管理者首页应满足：

1. 生产协同时间显示最新真实快照时间；
2. 如果仍为旧数据，显示“数据已过期 / 数据置信度不足”；
3. 旧生产数据不进入确定性订单交付风险结论；
4. 订单、齐套、质量、缺料时间不受生产域旧数据影响；
5. Evidence 中保留本次生产接口的 `data_as_of` 和错误/警告信息。

## 6. 建议的联调命令

中台环境使用真实鉴权调用，不要把密钥写入命令历史或文档：

```powershell
$base = 'https://<control-platform-host>/api/v1'
$headers = @{
  Authorization = 'Bearer <redacted>'
}

Invoke-RestMethod "$base/external/production/work-orders/list?page=1&page_size=20" -Headers $headers
Invoke-RestMethod "$base/external/production/operations/list?order_no=<real-order-no>&page=1&page_size=20" -Headers $headers
Invoke-RestMethod "$base/external/production/order-links/list?order_no=<real-order-no>&page=1&page_size=20" -Headers $headers
Invoke-RestMethod "$base/external/production/reports/list?work_order_no=<real-work-order-no>&page=1&page_size=20" -Headers $headers
Invoke-RestMethod "$base/external/production/capacity/list?date_start=2026-09-29&date_end=2026-10-29&page=1&page_size=20" -Headers $headers
```

联调回传内容至少包括：

- 五个接口的脱敏响应头和时效字段；
- 数据源最近同步时间；
- 是否存在旧快照、ETL 延迟或分页截断；
- 工序 0 条的原因；
- 生产数据负责人和预计修复时间。

## 7. Hub 侧配套修改建议

中台修复后，Hub 仍建议增加保护：

- 对生产域按 24 小时进行过期判断；
- 将生产五个接口的时效分开保留，不用最早时间代表整个生产域；
- 过期时降级为“数据置信度不足”，不输出确定性的延期、阻塞或交付承诺结论；
- 看板显示“数据基准 + 新鲜度状态”，而不是只显示 `MM/DD HH:mm`；
- 过期生产数据仍可供人工查看，但不得伪装成当前实时数据。

## 8. 责任边界与回退

### 中台负责

- 生产数据源和同步任务；
- 五个生产 API 的 `data_as_of`、`data_confidence`、`stale` 语义；
- 工序 0 条、订单关联数量和分页口径；
- 真实数据时效与数据源 Evidence。

### AEOS Hub 负责

- 只读调用、字段校验和展示；
- 过期数据降级和风险结论边界；
- Evidence / Attention 中保留时效告警；
- 不修改中台业务数据，不替中台生成数据时间。

### 回退策略

如果生产接口修复后出现错误：

1. 保留 `STALE_DATA` 或结构化不可用返回；
2. Hub 展示“生产协同暂不可用”；
3. 不回退到旧快照冒充实时数据；
4. 订单、齐套、质量和缺料链路继续独立运行。

## 9. 完成定义

以下条件全部满足后，视为本次中台交接完成：

- [ ] 五个生产接口已完成数据源刷新；
- [ ] 五个接口均返回真实 `data_as_of`；
- [ ] 过期数据会正确返回 `stale=true` 或低置信度；
- [ ] 工序 0 条原因已确认；
- [ ] 分页总数和数据快照口径已确认；
- [ ] Hub 刷新后生产协同不再显示旧时间，或明确显示过期状态；
- [ ] 生产数据时效告警已进入 Evidence；
- [ ] 中台平台组提供脱敏联调响应和负责人确认。
