## 三、建议一并接入（不阻塞联调）

| 项 | 中台侧做法 | 不做的后果 | 是否接入 |
|---|---|---|---|
| 推理 usage | 在推理响应里返回 `usage`：`model`、`input_tokens`、`cached_tokens`、`output_tokens`、`cost`（`cost` 可省） | 推理用量与成本看不到 |  |
| 执行步骤 run_event | 按执行步骤上报协议上报模型 / 工具调用 | Hub 时间线看不到推理内部过程 |  |

| request_id 透传 | 确认是否接受 Hub 在请求里带 `request_id`（=Hub runId），用于双方日志关联 | 联调排障只能按时间对日志 |  |

## 四、Hub 侧已完成

- 推理适配器：真实 HTTP 契约、召回中止、超时、5xx / 401 错误分别映射；
- 结果校验：结论缺 `evidence_refs` 或 `data_as_of` 时降为低置信度并附校验说明，不静默通过；
- usage 自动透传：上游响应带 usage 时自动记入用量台账，缺成本时按模型目录补算；
- 联调自检工具：中台给出地址当天即可逐条核对验收标准，失败项可直接回传；
- 中台网关：登录自启、崩溃守护、执行面允许列表配置化；
- 用量台账：区分已上报 / 未上报，支持按系统、Agent、模型聚合。

## 五、联调当天步骤

1. 中台提供第二节 15 项契约及 URL / Token / Agent ID；
2. Hub 侧配置 `TARGET_REASONING_*` 并重启网关；
3. Hub 侧跑联调自检，按项核对验收标准；
4. 登录 Hub，在执行面提一个分析类问题，确认返回结论与 evidence_refs；
5. 双方核对日志：确认实际调用了中台大模型 / 推理智能体，且 Hub 召回时上游请求被取消。

## 六、验收标准

1. 推理结果含 `conclusions`、`evidence_refs`、`data_as_of`，`data_confidence` 不是 low；
2. 无 `evidence_refs` 的结论被标记低置信度并附校验说明；
3. Hub 召回时，中台推理请求被真正中止；
4. 超时、5xx、401 分别返回明确错误码；
5. 中台日志能证明实际调用了大模型 / 推理智能体，而不是直查 REST 后伪装；
6. （可选）用量台账出现推理 Token / 成本；
7. （可选）执行步骤时间线出现模型 / 工具调用过程。
