# 新系统接入标准包

> 适用：任何业务系统通过统一网关接入 AEOS Hub（查询 / 分析 / 受控写）  
> 版本：2026-10-28  
> 参考（已按此标准接入）：公司中控平台 `gateway-control-platform`、恒剑 PLM `runtime-execution-query`  
> 本包分三部分：① 给接入系统的接入说明；② Hub 管理员配置清单；③ 验收用例模板。

---

# 第一部分：给接入系统（网关开发方）

## 1. 接入形态

- 一个系统 = **一个网关 Agent + 一套系统令牌**，反向 WebSocket 连接 Hub；
- 中台内部无论有多少智能体，都由网关收敛后对外声明能力，内部自行路由，用 `handled_by` 回报实际执行者；
- 不把内部智能体单独注册给 Hub。

```text
内部 Agent A / B / C…
    │ 网关内部路由（capability + operation / task_type）
    ▼
网关 Agent（唯一对外身份）
    │ WebSocket（反向连接 Hub）
    ▼
Hub：授权、审批、派单、审计
```

## 2. 连接与注册

- 地址：`ws://<Hub主机>:8788/execution-agent`（跨机/生产用 Hub 提供的统一入口）；
- 请求头：`x-aeos-system-id: <Hub分配的系统ID>`、`x-aeos-system-token: <Hub签发的系统令牌>`（令牌保密，不要入库/入日志）；
- 连接后发送 register：

```json
{
  "type": "register",
  "agentId": "<系统ID> 网关的唯一 AgentID，如 gateway-<系统标识>",
  "name": "<系统> 系统网关",
  "version": "1.0.0",
  "sourceSystem": "<系统ID>",
  "capabilities": [ ... 见第 3 节 ... ]
}
```

连接后须**定期发送心跳**（建议每 5 秒），否则 Hub 会在 15 秒后将其标记为离线：

```json
{"type":"heartbeat","status":"idle|working","currentRunId":"<当前执行的 runId，无则为 null>"}
```

- `status`：`idle`（空闲）或 `working`（正在执行任务）；
- `currentRunId`：正在执行的 runId，空闲时为 null；
- 收到 `dispatch` 后应先回 `run_update: running`，完成或失败后再回 `run_complete` / `run_failed`；
- Hub 派单后 30 秒未收到响应会标记为 `DISPATCH_TIMEOUT`。

## 3. 能力声明

每个能力 = `name` + `inputSchema`（JSON Schema）+ `constraints`（约束）+ 写操作另附 `operations` 元数据。

### 3.1 查询类能力（只读）

```json
{
  "name": "query_<系统标识>",
  "description": "<系统>只读查询",
  "inputSchema": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "enum": ["/external/... 可用端点白名单"] },
      "params": { "type": "object" }
    },
    "required": ["path"]
  },
  "constraints": { "readOnly": true }
}
```

### 3.2 分析类能力（只读推理）

```json
{
  "name": "reason_<系统标识>",
  "description": "<系统>只读分析",
  "inputSchema": {
    "type": "object",
    "properties": {
      "prompt": { "type": "string" },
      "task_type": { "type": "string", "enum": ["<按业务定义>"] },
      "context": {
        "type": "object",
        "properties": { "businessObjectRef": { "type": "string" } },
        "required": ["businessObjectRef"]
      }
    },
    "required": ["prompt", "task_type", "context"]
  },
  "outputSchema": {
    "type": "object",
    "properties": {
      "summary": { "type": "string" },
      "conclusions": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "matter": { "type": "string" },
            "evidence_refs": { "type": "array", "items": { "type": "string" } },
            "risk": { "type": "string" },
            "recommendation": { "type": "string" },
            "confidence": { "type": "string" }
          },
          "required": ["matter", "evidence_refs"]
        }
      },
      "evidence_refs": { "type": "array", "items": { "type": "string" } },
      "data_as_of": { "type": "string" },
      "data_confidence": { "type": "string" },
      "stale": { "type": "boolean" },
      "duration_ms": { "type": "integer" },
      "request_id": { "type": "string" },
      "handled_by": { "type": "object" }
    },
    "required": ["summary", "conclusions", "evidence_refs", "data_as_of", "data_confidence"]
  },
  "constraints": { "readOnly": true, "requireEvidence": true }
}
```

### 3.3 写类能力（受控写）

```json
{
  "name": "write_<系统标识>",
  "description": "<系统>受控写操作，仅接受 Hub 审批后的派单",
  "inputSchema": {
    "type": "object",
    "properties": {
      "operation": { "type": "string", "enum": ["<写操作白名单>"] },
      "<业务标识字段，默认 orderNo>": { "type": "string" },
      "changes": { "type": "object" },
      "idempotencyKey": { "type": "string" }
    },
    "required": ["operation", "<业务标识字段>", "changes"]
  },
  "constraints": {
    "readOnly": false,
    "approvalRequired": true,
    "idempotent": true,
    "riskLevel": "low | medium | high"
  },
  "operations": [
    {
      "name": "<操作名，如 xxx.update_yyy>",
      "title": "<中文标题>",
      "keywords": ["<用于意图匹配的关键词>"],
      "changesField": "changes",
      "fields": [
        { "name": "<字段名>", "label": "<中文标签>", "type": "string | date | number", "required": true }
      ]
    }
  ]
}
```

- `operations` 元数据是 Hub 解析写命令的依据（关键词定位操作、字段 label 抽值），**必须填写**；
- Hub 侧人工确认后才派单，网关不需要做审批。

## 4. 派单与回执

Hub 下发：

```json
{
  "type": "dispatch",
  "runId": "exec-run-...",
  "capability": "reason_xxx",
  "input": { ... 符合你声明的 inputSchema ... },
  "traceId": "...",
  "caller": { "systemId": "...", "agentId": null, "userId": "...", "taskId": null, "traceId": null },
  "request_id": "..."
}
```

- `caller.systemId` 不是本系统时，按**外部系统调用**处理：caller 只作审计元数据，**不要**用它的 userId 去查本系统用户表；
- `request_id` 原样回显到结果的 `request_id` 字段。

网关回执：

| 消息 | 时机 |
|---|---|
| `{"type":"run_update","runId":"...","state":"running"}` | 开始执行 |
| `{"type":"run_event","runId":"...","eventId":"...","event":"step_started|step_completed|run_summary","name":"<步骤名>","status":"started|completed",...}` | 关键步骤（可选，便于进度展示） |
| `{"type":"run_complete","runId":"...","result":{...},"usage":{"modelId":"...","tokensIn":n,"cachedTokens":n,"tokensOut":n,"cost":n}}` | 执行成功（`usage` 只在实际调用模型时上报） |
| `{"type":"run_failed","runId":"...","error":{"code":"...","message":"..."}}` | 执行失败 |
| `{"type":"recall","runId":"..."}` 收到后终止任务并回 `run_update: recalled` | Hub 召回 |

## 5. 错误码约定

| 场景 | 错误码 |
|---|---|
| 同一时刻已有任务 | `AGENT_BUSY` |
| 内部找不到处理 Agent | `AGENT_NOT_FOUND` |
| 指定 Agent 不匹配 | `TARGET_AGENT_UNAVAILABLE` |
| 上游不可用 / 超时 | `UPSTREAM_UNAVAILABLE` / `UPSTREAM_TIMEOUT` |
| 幂等冲突 | `IDEMPOTENCY_CONFLICT` |
| 参数不合法 | `INVALID_ARGUMENT` |

## 6. 约定与边界

1. 只读能力不得产生任何副作用；写能力必须幂等（同一 `idempotencyKey` 只执行一次）；
2. 写操作由 Hub 人工确认后才派单，网关不需要做审批；
3. 业务标识（订单号等）必须来自用户原话或系统数据，不得编造；
4. 数据必须带 `data_as_of` 与 `data_confidence`，缺失或过期明确标注；
5. 令牌保密；泄露立即通知 Hub 撤销重发。

# 第二部分：Hub 管理员配置清单

新系统接入时，Hub 侧只做**配置**，不改代码：

| # | 文件 / 操作 | 内容 |
|---|---|---|
| 1 | `data/systems.json` | 登记系统：`systemId`（唯一标识）、`name`（显示名）、`tenantId` |
| 2 | `config/execution-agent-allowlist.json` | `allowlist` 加入 `"systemId": ["<网关AgentID>"]`（准入） |
| 3 | `config/execution-agent-permissions.json` | `grants` 加入：系统 × Agent × 能力 × 租户（查询/分析/写分开授权） |
| 4 | `config/borrow-policy.json` | `allowlist` 加入系统可被跨系统借调的只读能力 |
| 5 | `scripts/mint-system-token.ts <systemId>` | 签发系统令牌，交给对方（不落库、不入聊天） |
| 6 | （可选）`config/execution-routing-policy.json` | 多系统提供同一能力时的选路顺序 |
| 7 | （可选）`config/conclusion-dispatch-policy.json` | 自动分发策略中加入新系统的分析操作 |

> 权限/白名单/借调策略均支持热加载，改完即生效，无需重启 Hub。

# 第三部分：验收用例模板

> 接入方与 Hub 各跑一遍；全部通过才算验收完成。

## A. 连接与注册

| # | 用例 | 预期 |
|---|---|---|
| A1 | 启动网关 | Hub 执行面出现该 Agent，在线 |
| A2 | 用旧根令牌连接 | HTTP 401 拒绝 |
| A3 | 令牌系统与自报系统不一致 | `SYSTEM_IDENTITY_MISMATCH` |
| A4 | 未在允许列表的 AgentID | `AGENT_NOT_ALLOWED` |

## B. 查询能力（逐端点）

| # | 用例 | 预期 |
|---|---|---|
| B1 | 每个查询端点带正确参数 | `completed`，返回数据 + `data_as_of` + `data_confidence` |
| B2 | 参数错误 | `INVALID_ARGUMENT`（中台 422 透传），不静默成功 |
| B3 | 并发第二笔 | `AGENT_BUSY`（确认单任务约束与错误码） |

## C. 分析能力（逐 task_type）

| # | 用例 | 预期 |
|---|---|---|
| C1 | 每类分析带业务锚点 | 完成，返回结构化结论 + `evidence_refs` + `handled_by` + `request_id` 回显 |
| C2 | 缺业务锚点 | 拒绝，不猜测 |

## D. 写能力（Hub 审批后逐操作）

| # | 用例 | 预期 |
|---|---|---|
| D1 | 三类操作各提交一笔 | 进入 `pending_approval`，**未审批不派单** |
| D2 | 未经审批直接派单 | `WRITE_FORBIDDEN` |
| D3 | Hub 人工确认 | 派单 → 完成返回 `before/after` + `handled_by` |
| D4 | 同 `idempotencyKey` 重复提交 | 返回首次结果，`idempotent_replay=true`；内容不同 → `IDEMPOTENCY_CONFLICT` |
| D5 | 内部无对应 Agent | `AGENT_NOT_FOUND`，不回退、不静默 |

## E. 稳定性与治理

| # | 用例 | 预期 |
|---|---|---|
| E1 | 杀网关进程 | 1 分钟内显示离线；Keeper/自愈拉起后自动重连，仍是同一 Agent |
| E2 | Hub 召回执行中任务 | 网关终止并回 `recalled` |
| E3 | 台账抽查 | 借调、审批、写操作、失败均有证据；不含令牌/密钥 |
| E4 | 30 天幂等、数据时效 | 按中台确认的规则执行 |
